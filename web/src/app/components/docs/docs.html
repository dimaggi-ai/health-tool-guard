System Design

Tool Guard Architecture

Tool Guard sits between every AI agent and every action it takes. The pipeline has five stages: Intercept → Evaluate → Decide → Explain → Audit. Deterministic rules complete in under 12 ms; semantically ambiguous cases route to Gemma 4 deep reasoning and complete in under 800 ms.

Pipeline stages

01
Intercept

The SDK wraps every agent tool call into an ActionEnvelope carrying agent identity, tool name, parameters, timestamps, language code, and modality metadata.

02
Evaluate

Fast deterministic rules execute first (<12 ms). If any deterministic policy triggers a hard DENY the evaluation stops. Otherwise, ambiguous cases are routed to the Gemma 4 hybrid evaluator.

03
Decide

Five possible outcomes: ALLOW, DENY, REDACT-AND-CONTINUE (strips PII and lets the sanitised action proceed), ESCALATE (honest handoff to a human or higher authority), or FLAG (proceed with a warning appended).

04
Explain

Gemma 4 generates a human-readable explanation for every decision — what happened, why it was triggered, and which policy rule was decisive.

05
Audit

A SHA-256 hash-chained record is written for every decision. Each record's prevHash is the hash of the previous record, making the chain tamper-evident and offline-verifiable.

Governance Rules

Policy Engine

Tool Guard ships two policy tiers. Deterministic policies are pure-function rule evaluators that run in under 12 ms with no model inference. Hybrid policies delegate to Gemma 4 when semantic reasoning is required. Deterministic rules always execute first; Gemma 4 is only invoked when all deterministic checks pass and at least one hybrid policy applies.

Deterministic Policies <12 ms
  • clinical-scope-lock — blocks tool calls that exceed the agent's declared clinical scope
  • pii-boundary — detects and redacts personal identifiers before data leaves the system
  • confidence-gate — denies tool calls where model confidence falls below the configured threshold
  • lingua-language-match — ensures the response language matches the patient's declared language
  • lingua-script-guard — rejects mixed-script output that could confuse non-Latin readers
  • rate-governor — enforces per-agent and per-tool rate limits
  • exfiltration-guard — blocks unexpected data destinations and oversized payloads
Hybrid Policies Gemma 4 <800 ms
  • contraindication-check — evaluates proposed drug combinations against the patient's allergy and medication history for semantic interaction risk
  • lingua-terminology-lock — verifies that medical terminology is rendered correctly in Tier 2 languages (Tagalog, Luganda)
  • lingua-reading-level — ensures patient-facing text stays within the appropriate reading-level band for the patient's declared literacy tier

Example: contraindication-check policy YAML

id: contraindication-check
tier: hybrid
evaluator: gemma4
description: >
  Detects drug-drug and drug-allergy interactions that require
  semantic reasoning beyond keyword matching.
trigger:
  tools: [prescribe_medication, order_medication, update_prescription]
  fields: [medication, dosage, patient_allergies, current_medications]
on_match: DENY
prompt_template: |
  You are a clinical safety evaluator. Given the patient context and
  proposed medication action, identify any contraindications.
  Respond ONLY with valid JSON: {{ '{' }}"decision": "ALLOW"|"DENY", "reason": "..."{{ '}' }}
latency_budget_ms: 800
fallback_on_timeout: ESCALATE

The two-tier architecture means safe, unambiguous tool calls are never unnecessarily delayed by LLM inference. Only the 15–20% of calls that involve semantic ambiguity (drug interactions, complex multilingual content) incur the Gemma 4 latency budget.

Evaluation Engine

Hybrid Evaluation Router

Deterministic rules catch known-bad patterns in microseconds. But real clinical safety requires semantic reasoning. A 2025 PMC study (PMC12712589) found a leading closed-frontier LLM detected only 46.83% of drug-drug interactions — meaning a purely LLM-based approach misses more than half. Tool Guard's hybrid router combines the speed of rule evaluation with Gemma 4's semantic depth, invoking the model only when rules are insufficient.

How the router decides

1
Run all deterministic policies

Every tool call is evaluated against all deterministic policies first. If any policy returns DENY, the call is blocked immediately — no model invocation, no latency cost.

2
Check hybrid policy applicability

The router inspects the tool name and fields against each hybrid policy's trigger spec. If no hybrid policy applies, the call is ALLOWED and the Gemma 4 path is never entered.

3
Invoke Gemma 4 with structured prompt

Applicable hybrid policies are bundled into a single Gemma 4 call using format=json to guarantee parseable output. num_predict=600 caps response length. temperature=0.1 minimises hallucination risk.

4
Parse and act on JSON decision

The model response is parsed as JSON. The format=json Ollama option suppresses thinking tokens from appearing in the structured output while still allowing the model to reason internally before emitting the result.

Gemma 4 prompt structure

{
  "model": "gemma4",
  "format": "json",
  "num_predict": 600,
  "options": { "temperature": 0.1 },
  "messages": [
    {
      "role": "system",
      "content": "You are a clinical safety evaluator for Tool Guard. Evaluate the proposed tool call against the active policies. Respond ONLY with valid JSON matching the schema: {\"decision\": \"ALLOW\"|\"DENY\"|\"REDACT\"|\"ESCALATE\"|\"FLAG\", \"policy\": \"policy-id\", \"reason\": \"one sentence\", \"confidence\": 0.0–1.0}"
    },
    {
      "role": "user",
      "content": "Tool: prescribe_medication\nPatient allergies: aspirin\nProposed medication: ibuprofen 400mg\nActive policies: [contraindication-check]\nEvaluate."
    }
  ]
}

Why format=json matters: Without structured output, LLMs embed their decision inside prose that requires fragile regex parsing. The Ollama format=json option constrains token sampling to produce valid JSON, making the policy evaluation pipeline deterministically parseable even when the model reasons about ambiguous clinical scenarios.

Tier definitions

Tier 1 — Full governance

All deterministic and hybrid policies applied. Gemma 4 was validated on this language in clinical domain prompts. Terminology lock and reading-level gate are active.

Tier 2 — Partial governance

Deterministic policies fully applied. Hybrid terminology policies applied with heightened scrutiny. Complex clinical content routes to ESCALATE rather than ALLOW.

Tier 3 — Honest escalation

Tool Guard does not pretend to govern what it cannot verify. All clinical tool calls in Tier 3 languages produce an ESCALATE decision with a human-readable explanation for the patient.

Evidence: PMC11729812 — systematic review of AI translation accuracy in medical settings, finding 33.3% clinically significant error rate. PA Patient Safety Journal 2024 — analysis of 336 safety events in LEP patients; 82.4% involved a communication failure as a contributing factor.

Compliance & Traceability

Tamper-Evident Audit Chain

Every Tool Guard decision — ALLOW, DENY, REDACT, ESCALATE, or FLAG — produces an immutable SHA-256 audit record. Each record's prevHash field is set to the SHA-256 hash of the previous record, forming a linked chain. Any deletion, reordering, or field modification breaks the chain and is detected by the offline verifier.

Audit record fields

{
  "id":          "rec_01jwzk...",
  "timestamp":   "2026-05-12T14:03:22.411Z",
  "tool":        "prescribe_medication",
  "decision":    "DENY",
  "evalPath":    "hybrid",
  "latencyMs":   412,
  "tokensUsed":  284,
  "policy":      "contraindication-check",
  "reason":      "Ibuprofen is contraindicated with aspirin allergy (cross-reactivity risk).",
  "hmac":        "sha256=a3f9...",
  "hash":        "e7c2b14d...",
  "prevHash":    "0000000000000000..."
}

Chain verification

The offline verifier recomputes every record's hash and checks that each prevHash matches the previous record's computed hash. HMAC signatures are also validated against the signing key. 

python3 verifier/verify.py verify --chain audit.jsonl

# Output (clean chain):
# Verifying 47 records...
# ✓ All hashes valid
# ✓ All HMACs valid
# ✓ Chain integrity confirmed

# Output (tampered record):
# ✗ Hash mismatch at record 23
# ✗ prevHash of record 24 does not match record 23
# Chain integrity FAILED — 1 break detected

What tamper detection catches

Record deletion

Removing any record causes the next record's prevHash to no longer match — detected immediately.

Record reordering

Swapping two records breaks the hash chain at the point of swap — both positions are flagged.

Field modification

Changing any field (decision, reason, latency) invalidates that record's hash and every subsequent prevHash.

Integration

Live Agent API

The POST /api/agent endpoint runs a full agentic loop: Gemma 4 acts as a clinical triage agent, receives a patient description, and proposes tool calls. Tool Guard intercepts each proposed tool call in real time, evaluating it against the active policy set before the action is permitted to proceed. The response includes every tool call, every Tool Guard decision, and the agent's full reasoning trace.
